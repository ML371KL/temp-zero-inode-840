# Аудит гейтов отсева (2026-08-16)

Повод — сделка CFO AbCellera на панели: покупка 37 200 акций по $10.32 от 14.08.2026
получила отсев «цена ниже рынка (похоже на размещение)». Проверка первоисточника показала,
что отсев ошибочный, а разбор механизма вскрыл дефект, затрагивающий около 40% всех
срабатываний этого гейта.

## 1. Разбор конкретного случая: ABCL, Booth Andrew

Первоисточник — Form 4, accession `0001834411-26-000008`:

```
periodOfReport   2026-08-14
transactionDate  2026-08-14
transactionCode  P
shares           37200
price            10.32
aff10b5One       0            (плана 10b5-1 нет)
footnotes        (пусто)
remarks          (пусто)
officerTitle     Chief Financial Officer
ownership        D (прямое)
```

Парсер прочитал форму верно. Гейт сработал так:

| | |
|---|---|
| цена сделки | $10.32 |
| закрытие 14.08 | $11.38 |
| отношение | 0.9068 → скидка **9.3%** |
| порог `DISCOUNT_LIMIT` | 8% |

Теперь настоящие внутридневные диапазоны (Yahoo OHLC):

| Дата | Откр. | Макс. | Мин. | Закр. | Объём |
|---|---|---|---|---|---|
| 2026-08-10 | 8.76 | 10.01 | 8.40 | 9.34 | 46.0 млн |
| 2026-08-11 | 9.42 | 10.29 | 9.02 | 9.76 | 18.4 млн |
| 2026-08-12 | 9.22 | 10.38 | 9.00 | 10.35 | 14.9 млн |
| **2026-08-13** | **10.32** | 11.06 | **10.22** | 10.97 | 20.1 млн |
| 2026-08-14 | 10.84 | 11.50 | 10.47 | 11.38 | 12.3 млн |

**Цена $10.32 — это ровно цена открытия 13 августа, и она лежит внутри диапазона того дня
(10.22–11.06).** От минимума 14 августа она отличается на 1.4%.

Бумага прошла с $5.39 (29 июля) до $11.38 (14 августа) — **+111% за 11 сессий** при дневных
диапазонах около 10%. В таких условиях сравнение цены исполнения с закрытием того же дня
не несёт информации: любое исполнение в первой половине растущего дня выглядит «скидкой».

Содержательно версия размещения не выдерживает проверки: размещения продают институционалам
блоками, а здесь финансовый директор купил на $384 тыс. в прямое владение, увеличив личный
пакет на 8%, без сносок и без галочки 10b5-1. **Отсев ошибочный.**

## 4. Дефект гейта `discount`: сравнение только с закрытием

Гейт (`gates.mjs:126–131`) сравнивает цену сделки исключительно с **закрытием** дня:

```js
if (ctx.close && row.px) {
  const ratio = row.px / ctx.close;
  const limit = fn.wavg ? DISCOUNT_LIMIT_WAVG : DISCOUNT_LIMIT;
  if (row.code === 'P' && ratio < 1 - limit) return drop('discount');
}
```

Ценовой кэш (`data/prices/*.csv.gz`) хранит только `дата, close, adjclose, volume` —
**внутридневного диапазона в нём нет**, поэтому отличить «инсайдер купил на минимуме дня» от
«инсайдеру продали со скидкой вне рынка» гейт физически не может.

### Измерение

Взята выборка из 200 тикеров с отсевом `discount` начиная с 2022 года, для каждой строки
загружен настоящий дневной OHLC, исключены тикеры со сплитами после сделки (иначе Yahoo
отдаёт скорректированные цены и сравнение бессмысленно). Осталось **290 строк**:

| Что на самом деле | Строк | Доля |
|---|---|---|
| цена торговалась **в этот же день** (внутри low–high) | 88 | 30.3% |
| цена торговалась в соседний день (сдвиг даты в форме) | 41 | 14.1% |
| цена **ниже** диапазона трёх дней — похоже на размещение | 161 | 55.5% |

**Около 44% срабатываний гейта — доказуемо ложные: по этой цене в эти дни реально шли
сделки на бирже.** Случай ABCL попадает во вторую строку таблицы.

Дополнительный признак того же дефекта: доля отсева резко растёт с волатильностью бумаги.
У бумаг с дневной сигмой ≥7% порог «8% ниже закрытия» — это меньше 1.2 сигмы, то есть
обычный внутридневной ход, а не скидка.

### Порядок гейтов

`discount` проверяется **раньше** `sync` (строки 130 и 134). Из 3 190 отсеянных по `discount`
строк с известной ценой **41.4% поймал бы и `sync`** (≥3 филеров по одной цене) — у них есть
независимое подтверждение размещения. У оставшихся 1 870 строк такого подтверждения нет
вовсе, и решение принимается только на основе сравнения с закрытием, надёжность которого
измерена выше.

### Что предлагается

| Правило | Ловит настоящие | Гасит ложные | Нужны новые данные |
|---|---|---|---|
| сейчас: `px < close × 0.92` | 161/161 (100%) | 0/129 (0%) | нет |
| **A:** `px < min(close, пред.close) × 0.92` | 148/161 (92%) | 96/129 (74%) | нет |
| **D:** `px < min(low, пред.low) × 0.98` **И** `px < close × 0.92` | 155/161 (96%) | 121/129 (94%) | нужен `low` в кэше |

Оговорка о честности: эталон «настоящего размещения» здесь определён через минимумы дней,
поэтому правила B/D частично подогнаны под определение. Независимое подтверждение — сама
классификация по OHLC (торговалась цена или нет) и разбор ABCL, а не эти проценты.

- **Вариант A** внедряется сегодня на текущих данных и убирает три четверти ложных
  срабатываний, теряя 8% настоящих. Он лечит ровно тот механизм, на котором сломался ABCL, —
  рост цены внутри дня.
- **Вариант D** — правильное решение: добавить колонки `low`/`high` в ценовой кэш. Это смена
  схемы `data/prices/*.csv.gz` и перезакачка 5 148 тикеров.

## 5. Обратная сторона: пропускают ли гейты то, что надо отсеять

Проверена выборка из 489 **прошедших** строк (те же условия: OHLC, без сплитов после сделки):

| Что искали | Найдено | Комментарий |
|---|---|---|
| цена ниже минимума трёх дней (реальное размещение проскочило) | **2 / 489 (0.4%)** | скидки 4% и 5% — ниже порога 8% |
| цена выше максимума трёх дней (сделка не по рынку) | 7 / 489 (1.4%) | закрытые фонды HEQ, JHS (покупка по СЧА, а не по рынку), ADR CSAN, REZI |

**Значимой недоработки нет.** Порог 8% не пропускает размещения сколько-нибудь массово.
Единственная маленькая необслуженная категория — покупки в закрытых фондах по СЧА, которые
торгуются с дисконтом к рынку; их 1.4%, и отдельного гейта они не заслуживают.

Отдельно: первая версия этой проверки дала «4.1% прошедших с невозможной ценой», но это был
артефакт самой проверки — Yahoo отдаёт исторические цены скорректированными на сплиты
(CMG 50:1 в 2024, BDX, CLBK), а конвейер восстанавливает номинал через `nominalFactor()`.
После корректного исключения таких тикеров осталось 1.4%. **Ценовой слой в этой части
работает верно.**

## 6. Итог

| Гейт | Состояние |
|---|---|
| sync, newlisting, fund, routine, drip, security, noliq, offering, outlier, capacity, badvalue, forced | работают, отсеянные строки заметно хуже прошедших |
| planned, espp | выглядели подозрительно, реабилитированы поправкой на концентрацию эмитентов |
| regular, units | нейтральны — не вредят, но и пользы почти не приносят |
| **discount** | **механизм дефектен: ~44% срабатываний ложные, требуется учёт внутридневного минимума** |

Дефект не разрушает стратегию (как группа отсеянные по `discount` близки к базе), но
регулярно ставит ложную метку на добросовестных покупках менеджмента в быстро растущих
бумагах — именно на тех, которые интересны пользователю панели.
