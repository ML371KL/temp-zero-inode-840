# Вечерняя схема на бумаге

Статус: сбор с VPS идёт 2–3 месяца на бумаге; настоящий контур не строится (независимая проверка 04.11.2026:
«перспективно, не доказано» — через 5–30 минут после приёма до открытия D+1 остаётся ещё +0,35–0,45%, t≈3, 2,5 месяца данных).

## Что измеряем

Для каждой покупки P обыкновенных акций (сумма формы от $10 тыс.) из Form 4, **принятой EDGAR с 16:00 до 20:00 по Нью-Йорку**,
сборщик фиксирует котировку бумаги и IWM:

- в момент обнаружения формы (M0) и через **5, 15 и 30 минут после времени приёма** (M5, M15, M30);
- поля: bid, ask, последняя сделка вечерней сессии и её время, состояние рынка, источник, запоздание снятия.

Бумажные сделки на каждом событии (все — сверх IWM за то же окно, после издержек):

| Схема | Вход | Выход |
|---|---|---|
| E5 / E15 / E30 → закрытие | по ask через 5 / 15 / 30 минут после приёма | закрытие D+1 |
| E5 / E15 / E30 → открытие | то же | открытие D+1 — сколько ночного скачка взято |
| Текущая | открытие D+1 | закрытие D+1 — на тех же событиях |

IWM берётся в тот же момент (середина честной книги, иначе последняя сделка) и до того же выхода. Сравнение — **на одном наборе
событий**: только формы, у которых есть полный набор котировок на 5, 15 и 30 минут (по бумаге и по IWM), чей D+1 закрыт, и которые
входят в список панели (гейты, оборот ≥ $10 млн, цена ≥ $5). Отдельно — основной список (скор ≥ 2) и «все от $10 млн».
В покрытии блока: событий, в списках, D+1 закрыт, полный набор котировок, доля цен по оценке спреда.

**Издержки:** у вечерней схемы 0,08% на круг (комиссии IBKR 0,04% + влияние аукциона на стороне продажи 0,04%) —
`EVENING.cost` в `scripts/lib/evening.mjs`; спред уже внутри, раз покупка по ask. У текущей схемы — по уровню оборота (0,10% / 0,15% на круг:
в них оба аукциона). Константы — единственное место, где это меняется.

**Если честного bid/ask нет:** цена покупки — последняя вечерняя сделка × (1 + 0,2%) (консервативно: как если бы она прошла по bid),
в журнале и в блоке помечена как оценка (`estShare`); сделка старше 10 минут дополнительно помечается `stale`.
Книга «годна», только если оба числа есть, ask ≥ bid и разрыв не шире 1% от середины.

## Источники котировок (проба 04.11.2026, пре-маркет 08:05 ET; вечерняя проба — ниже)

- **Yahoo v7 (через воркер radar840-quotes).** Вне основной сессии bid/ask ненадёжны: AAPL 323.80 / 337.35 при цене 337 (разрыв 4%),
  IWM 0 / 0, MGM bid 31.80 / ask 0. Зато отдаются цена пред- и постсессии и время сделки (`preMarketPrice/Time`, `postMarketPrice/Time`).
  Воркер теперь возвращает всё как пришло: `b, a, bs, as, pp, pt, pre, prt` (ноль и «нет данных» — `null`); пригодность книги
  решает сборщик. Воркер отвечает на запросы с сервера без заголовка Origin (HTTP 200).
- **api.nasdaq.com** (`/api/quote/{SYM}/info`). В пре-маркете отдал `primaryData` с bid/ask, их размерами, последней сделкой и временем
  (AAPL 337.11 / 337.30, `isRealTime: true`) — то есть настоящая вечерняя книга. Проба шла с заголовками обычного браузера; подбор
  заголовков и обход защиты я не продолжал, и сборщик такого не делает: запрос — с честным User-Agent проекта, включается
  `EVENING_NASDAQ=1`, а закрытый адрес виден в журнале (`http`, `err`). **С адресом VPS не проверено** — это первая вещь, которую покажет вечер.
- Cboe delayed quotes: задержка 15 минут — для минутной схемы не годится.
- Если у nasdaq с VPS не получится, а книга Yahoo останется негодной: Tiingo IEX (ключ проекта уже есть; IEX-часть книги, вечером до 17:00 ET)
  или бесплатный ключ Alpaca (IEX) — проверять отдельно; до тех пор работает оценка спреда с честной пометкой.

## Как устроено

```
VPS (insider840-evening.timer, пн–пт 15:55 ET)
  collector.mjs: лента EDGAR getcurrent (type=4, owner=only) раз в минуту ─► полный .txt новой формы ─► parseForm4Txt
        │   время приёма — <ACCEPTANCE-DATETIME>; в окне 16:00–20:00 ET и покупка P ≥ $10 тыс. ─► событие
        └─► котировки (воркер radar840-quotes; опционально api.nasdaq.com) в M0 и через 5/15/30 минут после приёма
  журнал /var/lib/insider840-evening/paper/log/ГГГГ-ММ-ДД.jsonl ─► git push в ветку paper (отдельный deploy-ключ)
GitHub Actions (daily.yml)
  забирает ветку paper в data/paper ─► compute.mjs: события × списки × открытия D+1 ─► morning.json, блок `paper` ─► панель
```

Журнал (JSONL, по строке): `event` (id = номер формы, тикер, дата подачи, время приёма, сумма), `q` (id, момент, тикер или IWM, bid, ask, last,
lastT, состояние, источник, `late` — запоздание в секундах, `due`, `got`), `run`/`stat` — служебные. Перезапуск безопасен: состояние
читается из журнала, дублей нет.

К SEC — только `politeFetch` с `SEC_UA`, не чаще 5 запросов в секунду; опрос ленты — с пагинацией до 300 записей (в пик вечера новых форм
больше ста в минуту). **Замечание про ленту:** параметр `type=4` — префиксный фильтр (в ответ попадают 424B2, 497, 485…), поэтому взят
`owner=only` — только Form 4 (в варианте `owner=include`, как в задании, 26 форм из 56 записей).

Воркер, а не Cloudflare Cron + D1: бесплатных подзапросов в воркере 50 на вызов (форм в минуту больше), SEC считает лимит честного доступа по адресу,
а у Cloudflare адреса общие, а в ветку paper всё равно нужен push — для воркера это GitHub API с токеном в
секретах. VPS уже держит шаблон панелей (юнит, хардненинг, тревога через `dash-alert`), код сборщика — тот же Node, что и парсер форм.

## Выкладка

См. `ops/insider840-evening/README.md`: ключ `deploy-840-paper` (ed25519, с правом записи), установка `install.sh`, строка в `dash-alert`,
проба `scripts/evening/probe-quotes.mjs` вечером по Нью-Йорку, выкладка воркера `worker.yml` при слиянии PR.

Безопасность deploy-ключа: ключ репозитория с записью может писать в **любую** ветку, включая `main`. Если это недопустимо — защитить `main`
(branch protection с обязательным PR) или вынести журнал в отдельный репозиторий `temp-zero-inode-840-paper`; код менять не придётся
(только `PAPER_REMOTE`, а `daily.yml` — один адрес в шаге забора).
