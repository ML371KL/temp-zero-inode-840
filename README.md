# 📡 Инсайдерский радар

Дашборд инсайдерских сделок по SEC EDGAR Form 4. Главный экран — **рабочий набор**:
единственная конфигурация, у которой превышение над S&P 500 пережило независимую проверку.
Плюс лента всех покупок с причинами отсева, карточки тикеров и портфельная статистика.

**Вселенная:** NYSE + Nasdaq (+CBOE), без OTC. **История:** с 2016 года.
**Сигнал:** только покупки на открытом рынке (код P); продажи собираются как контекст
карточки тикера — предсказательной силы у них нет (проверено).

## Архитектура

```
SEC (квартальные датасеты Forms 3/4/5, 2016q1+) ─┐
SEC daily-index + XML Form 4 (живой хвост)       ├─> data (ветка-снапшот, форс-пуш)
Yahoo chart API (adjclose; Stooq — резерв)       ┘      ├─ trades/YYYY.json.gz + live.json.gz
                                                        ├─ prices/<T>.csv.gz (date,close,adjclose)
compute.mjs ──> site/data/*.json ──> GitHub Pages       └─ state/*.json (резюмируемость)
```

- **`scripts/backfill.mjs`** — квартальные структурированные датасеты SEC (идемпотентно, резюмируемо).
- **`scripts/live.mjs`** — дни после последнего датасета: daily-index → полные .txt → XML-парсер.
  Дедуп: строки, покрытые датасетами, вычищаются; поправки 4/A замещают исходники по содержательному ключу.
- **`scripts/prices.mjs`** — цены: полная замена кэша при каждом обновлении (adjclose пересчитывается
  задним числом после дивидендов — дозапись хвоста дала бы разрыв); защита от деградации ответа
  (свежий ряд короче половины кэша не принимается — сохраняет делистнутые при исчезновении из Yahoo).
- **`scripts/compute.mjs`** — гейты информативности, признак рабочего набора, календарно-временные
  портфели с альфой к трём факторам, payload.
- **`scripts/notify.mjs`** — Telegram: сделки, попавшие в рабочий набор. Без секретов молчит.

## Конвейер информативности (главное отличие от бесплатных скринеров)

Код `P` в Form 4 означает «покупка на открытом рынке **или частная**». Участие в PIPE,
допэмиссии, rights offering и DRIP приходит тем же кодом и в наивном скринере выглядит
как кластер инсайдерских покупок — хотя это привлечение капитала, а не сигнал уверенности.
Каждая покупка проходит гейты (детали: [docs/ПРОЕКТ.md](docs/ПРОЕКТ.md) §1):

```
дедуп 4/A → код P/класс бумаги → санити цены → сноски (размещение/DRIP/ESPP/принудительная)
 → дисконт к рынку → синхронные подачи → только юрлица → план 10b5-1 → рутинность CMP
```

На реальных данных отсеивается **около трети** «инсайдерских покупок». Отсеянные не
удаляются: они видны в ленте с причиной и участвуют в бэктесте — на экране «Статистика»
можно проверить, что гейты режут именно шум.

## Слой качества данных (2026-08)

Гейты и признак набора — функции от ценового ряда, поэтому испорченный ряд обесценивает
любую проверку, сколь угодно аккуратную. Что защищает данные:

- **Принадлежность тикера.** Символы в США переиспользуются, а справочник SEC знает только
  живые компании — у делистнутого эмитента тикер берётся из старой формы, и котировки по нему
  запрашиваются сегодняшние. К покупкам Legacy Reserves (2017–2019) так подставлялся ряд
  бумаги, занявшей `LGCY` в 2024-м. Теперь дата сделки сверяется с интервалами владения
  символом из открытого реестра Tiingo (`reference/symbol-ranges.json.gz`, без ключа);
  несовпадение = причина отсева `reassigned`. Проверка применяется только там, где тикер
  взят из старой формы: при живом CIK справочник SEC сам даёт нынешний символ.
- **Площадка на дату сделки.** Раньше мёртвый эмитент всегда получал категорию `unknown` и
  попадал во вселенную, даже если бумага никогда не торговалась на бирже. Тот же реестр даёт
  биржу на дату — из выборки ушло 1392 внебиржевых тикера и 26 тыс. покупок.
- **Санитайзер ряда.** Одиночные «залётные» бары (склейка двух инструментов под одним
  символом: у `ITC` настоящие бары по $40 шли вперемешку с чужими по $7800) снимаются
  медианным фильтром по окну **±30**. Уровневый сдвиг цены не трогается — удалить настоящий
  бар хуже, чем оставить подозрительный. Ответ Yahoo с чужой валютой или не-акцией
  отвергается до разбора баров.
  Окно расширено с ±7 в августе 2026: чужие бары приходят блоками, и у `ITC` блок из 16 штук
  по $15 000 старое окно не перекрывало — месячная доходность бумаги в панели доходила до
  +540 000%. Чтобы расширение не съедало настоящие всплески (короткое сжатие для медианного
  фильтра выглядит как выброс), бар с **подтверждающим объёмом** не снимается: у чужого
  инструмента объём свой и обычно низкий, у настоящего движения — взрывается. Исключение —
  отклонение в десять и более раз: такого движения за день с возвратом не бывает ни при каком
  объёме. Проверка идёт в три прохода: у блока чужих баров крайние видно только после того,
  как убрана середина.
- **Ремонт ряда по внешним источникам истины (2026-08).** Три болезни, три лекарства
  (`lib/prices.mjs`, применяются на чтении кэша — источник отдаёт часть из них и сегодня,
  поэтому разовая правка файлов бессмысленна):
  1. *Нескорректированный сплит.* Yahoo отдаёт событие в `events.splits`, а ряд иногда
     оставляет в номинале: у `TTOO` 12.10.2022 цена $5.60, 13.10.2022 (обратный сплит 1:50) —
     $255. Скачок сверяется с коэффициентом в окне ±3 бара; при совпадении история
     переводится в посплитовые единицы (цена /k, объём ×k). Дата события у источника съезжает
     на день-два, а сам коэффициент бывает неточным (`FFAI`: в реестре 1:150 на 24.07.2026,
     фактически ×96 днём раньше) — тогда за истину берётся наблюдённый скачок. Обязательное
     условие — в ряду есть ступень: без него правило «чинило» уже корректные ряды.
  2. *Чужой инструмент под тем же символом.* Всё вне последнего непрерывного интервала
     листинга из реестра символов — другая бумага: у `ITC` листинг кончился 24.10.2016, а в
     кэше бары до 2022 года; у `CHRD` интервалы 2001–2010 и с 20.11.2020, и ровно на границе
     ряд прыгает с $0.12 на $31 (старый капитал погашен в банкротстве). Режется только там,
     где на границе есть РАЗРЫВ (пауза ≥30 дней или скачок вдвое): иначе правило снимало бы
     переименования, у которых ряд непрерывен (`TICC`→`OXSQ` терял 213 строк).
  3. *Остаток.* Сдвиг уровня впятеро, которого нет ни в реестре сплитов, ни в реестре
     символов (`COSM` 16.12.2022: $0.33 → $23.01). Коэффициент восстановить не из чего,
     поэтому ряд обрезается, а не пересчитывается: потерять историю честнее, чем выдумать
     доходность. Режутся только скачки ВВЕРХ — обвал впятеро это чаще всего настоящий обвал,
     и вырезать его значило бы стереть реальный убыток.
- **Делистинг отличается от устаревшего кэша.** Признаком делистинга было «последний бар
  старше двух недель», но в режиме `daily` обновляются только тикеры с покупками за 25
  месяцев — у остальных ряд обрывается там, где его последний раз качали, и движок закрывал
  по ним позиции по старой цене. Теперь делистинг требует подтверждения реестром символов, а
  устаревшие ряды дозагружаются порциями (`prices.mjs`, режим `daily`).
- **Санити формы.** Числа Form 4 не валидируются SEC: встречается «5 079 100 акций по
  $253 995.06». Такие строки получают причину `badvalue` и не портят долларовые показатели.
- **Остаток владения (схема шардов v3).** Остаток `SHRS_OWND_FOLWNG_TRANS` относится к
  КОНКРЕТНОЙ форме владения — прямой пакет и пакет «через траст» это разные счётчики, а не
  одно число на лицо. Одна покупка при этом почти всегда разбита на несколько ценовых строк
  с НАРАСТАЮЩИМ остатком. Раньше строки агрегировались без признака D/I, а остаток брался
  из случайно последней строки: прирост позиции `dOwn` ошибался на порядок (у HY 2019-03-27
  выходило +500% вместо +1%). Теперь остаток считается по форме владения, внутри формы
  берётся итоговый (наибольший у покупок, наименьший у продаж), смешанная строка помечается
  `di='M'` и отдаёт прирост только по прямой части. Замер на трёх кварталах: **8.5% строк
  меняют `dOwn`**, известен он у 99.3% против 98.1%, доля «докупка ≥20%» падает на 5%.
  Остаточное ограничение: у одного лица бывает НЕСКОЛЬКО косвенных пакетов (траст, супруга,
  LLC), и Form 4 не даёт им структурного ключа — такие строки отдают `dOwn = null`, а не
  правдоподобное число. Миграция схемы идёт без остановки прода: строки замещаются на месте.
- **Выжившесть измеряется, а не замалчивается.** Блок `quality` в `meta.json`: сколько строк
  отсеяно чужим тикером, у скольких вход невозможен (ряд начинается позже подачи), сколько
  баров снято фильтром, пересчитано по сплитам, обрезано по реестру и срезано по разрыву.
  Блок `survival` — доля покупок БЕЗ ценового ряда **по годам**, и она же выводится на экран
  Статистики: 36% в 2016 году против 1% в 2026. Одно суммарное число эту зависимость прячет,
  а она и есть суть проблемы — ряды исчезают не случайно, а вместе с компаниями, которых
  больше нет. Настоящая дыра — 1512 тикеров, действительно торговавшихся на бирже
  в дату сделки; закрывается `scripts/tiingo.mjs` (Yahoo делистнутых не отдаёт, Stooq закрыт
  антиботом). Бесплатный тариф Tiingo — 500 уникальных символов в месяц, поэтому очередь
  приоритетная по экономическому весу и резюмируемая; без секрета `TIINGO_TOKEN` шаг молчит.

## Главная метрика Статистики — календарно-временной портфель (2026-08)

Прежней метрикой было среднее избыточной доходности **по сделкам**. Она отвечала на вопрос
«сколько принесла средняя подача», а не «сколько принёс бы портфель», и оказалась смещена
вверх. Замер: 100 подставных выборок, где даты сигналов сохранены, а тикеры взяты случайно из
той же вселенной той же ликвидности, — сырое среднее показывает медиану **+5.0%** при
коридоре 5–95% [+2.7 … +8.6]. То есть «сигнал +8%» стоял на три пункта выше собственного
шумового пола.

Выбор метрики сделан замером, а не вкусом. Три кандидата по трём критериям:

| метрика | смещение на подставных | ширина коридора | расхождение оценки между половинами выборки |
|---|---|---|---|
| сырое среднее по сделкам | **+5.0%** | 5.9 п.п. | 15.3 п.п. |
| винзоризованное 1% | +0.5% | 1.6 п.п. | 15.0 п.п. |
| **портфель (принят)** | **−0.2%** | **1.2 п.п.** | **3.2 п.п.** |

Метрика по Jeng–Metrick–Zeckhauser: на конец месяца берём все бумаги с квалифицирующей
подачей за последние H месяцев, равный вес **по тикерам** (не по сделкам), держим месяц.
Показываются годовая альфа к двум факторам (рынок и наклон размера), её t-статистика с
поправкой Ньюи–Уэста, отдельно обе половины выборки, а также превышение над равновзвешенной
вселенной той же ликвидности. Порог оборота $3 млн/день на момент покупки: ниже него портфель
неторгуем и сравнение бессмысленно.

Важное свойство: **ранговая корреляция оценок ячеек между половинами выборки близка к нулю у
ЛЮБОЙ метрики** (0.06 у сырого среднего, −0.25 у портфельной). Экран Статистики не позволяет
надёжно ранжировать срезы — и новая метрика этого не скрывает, потому что показывает обе
половины рядом и порог значимости. Реализация и обоснование: `scripts/lib/portfolio.mjs`.

## Что даёт альфу к S&P 500 (2026-08)

Ключевой факт, меняющий прочтение всех прежних выводов: **равновзвешенная вселенная
ADV≥$3 млн, из которой отбираются сигналы, сама проигрывает индексу** — около 10% годовых
против 14% у SPY. Значит сигналу нужно набрать 3–5 п.п. сверх сопоставимых бумаг просто
чтобы сравняться с S&P 500, и «лучше вселенной» ≠ «лучше индекса».

**Рабочий набор** — единственная конфигурация, у которой превышение над индексом пережило
все проверки: покупка инсайдера при цене не ниже 5% от 52-недельного максимума, на сумму
от $50 тыс., в бумаге с оборотом от $3 млн в день; удержание три месяца, равный вес.
Около 27 позиций, медиана восемь сигналов в месяц.

| | набор | S&P 500 |
|---|---|---|
| CAGR / волатильность / просадка | ~23% / 19% / −30% | ~14% / 14.5% / −24% |
| коэффициент Шарпа | **1.07** | 0.86 |
| превышение над индексом | **+7.5%/год (t≈2.1)**, IR 0.58 | — |
| альфа к трём факторам (рынок, размер, моментум) | **+7.7% (t≈2.3)** | — |
| сверх бумаг того же ценового контекста | **+8.2% (t≈2.8)** | — |
| нетто после издержек 0.5% на круг | **+5.7%** | — |

Доказательства (считаются каждой сборкой и показаны на вкладке Статистика): монотонность
обеих отсечек, затухание при задержке входа, год за годом против индекса, перестановочный
тест против случайных бумаг того же ценового контекста (p < 0.001).

**Альфа считается к ТРЁМ факторам.** Моментум обязателен: набор отбирает бумаги у
52-недельного максимума и по построению сидит в победителях моментума. Прежняя
двухфакторная метрика (рынок + наклон размера) завышала результат любого ценового набора.

Полный разбор — что работает, что нет и почему панель выглядит именно так:
**[docs/ЧТО-РАБОТАЕТ.md](docs/ЧТО-РАБОТАЕТ.md)**.

## Что убрано и почему (2026-08)

Панель сокращена до того, что пережило независимую проверку. Удалены не «на всякий
случай», а с числами:

- **кластеры инсайдеров** — альфы не дают ни на одном горизонте, внутри рабочего набора
  одиночные покупки лучше кластерных (+8.4% против +2.9%);
- **балльный скор** — к индексу не выводил (вероятность превышения по бутстрэпу 0.50),
  внутри набора ничего не добавлял;
- **рейтинг инсайдеров по трек-рекорду** — доля успеха ≥60% и <40% дают одинаковый
  результат, экран ранжировал шум;
- **агрегатный рыночный индикатор** — за десять лет ни одного месяца в сигнальной зоне;
  альфа набора от режима рынка не зависит;
- **признаки «после отчёта»/«перед отчётом»** и шаг сбора дат отчётности — внутри набора
  условие «после отчёта» даёт +0.2% против +9.0% без него.

Продажи инсайдеров проверены и НЕ добавлены: портфель проданных бумаг неотличим от
сопоставимых (+0.1%, t=0.19) — ни как сигнал к продаже, ни как повод избегать покупки.

## Ключевые решения (не «чинить» без понимания)

1. **Вход бэктеста — закрытие первого торгового дня после даты ПОДАЧИ** (не даты сделки):
   сигнал публичен только с подачи формы; вход по дате сделки был бы забеганием вперёд.
2. **Excess vs SPY по adjclose** (тотальная доходность обеих сторон). Голая доходность в бычьем
   рынке всегда «работает» — это иллюзия.
3. **Делистнутые не выбрасываются**: закрываются последней ценой и показываются отдельной
   колонкой. Эмитенты без единой цены не входят в бэктест, но их число видно в meta —
   остаточная ошибка выжившего задокументирована, а не спрятана.
4. **Ветка data — одиночный снапшот-коммит с форс-пушем**: кэши цен переписываются целиком,
   при обычных коммитах репозиторий рос бы на десятки МБ в день.
5. **Тикер резолвится через CIK по текущему справочнику SEC** (переименования вроде FB→META),
   для отсутствующих в справочнике — тикер из самой формы (кандидаты в делистинг).
6. **Код P агрегируется по (accession, code, дата, класс бумаги)**: множественные строки одной
   сделки по разным ценам сворачиваются в vwap. Гранты (A), опционы (M), налоги (F), дарения (G),
   свопы — не сигнал.
7. **Stooq-резерв не обходит антибот-челлендж**: HTML-ответ = источник честно помечается недоступным.
8. **Сплит-факторы обязательны**: колонка close у Yahoo пересчитана задним числом, а инсайдер
   платил номинальную цену своего времени. Без коэффициентов обратный сплит 1:20 делает
   историческую котировку в 20 раз выше фактической, и гейт дисконта ложно срабатывает.
9. **Трек-рекорд инсайдера — строго point-in-time**: в скор входят только прошлые покупки,
   чьё 6-месячное окно закрылось до текущей подачи. Иначе скоринг знал бы будущее.
10. **Кластер считается по независимым физлицам**: фонд, его GP и партнёры, подавшие одну
    форму, — один участник, а не три. Склейка через граф совместных подач, но ОТДЕЛЬНО по
    юрлицам и по физлицам: сплошная склейка была транзитивной, и независимые директора разных
    эмитентов, подававшие формы вместе с одним фондом, становились «одним покупателем».
    В крупнейшей группе так слиплись 396 CIK, включая Шварцмана и девять директоров; всего это
    затрагивало 3418 физлиц из 72 515 и занижало размеры кластеров.
11. **Числа наборов считает сборка, а не разметка.** Определения наборов лежат в
    `compute.mjs` (`RECIPE_DEFS`) рядом с фильтром ленты, результаты — в `stats.recipes`,
    страница их только показывает. Раньше таблица и подписи чипов были строками в HTML,
    считанными скриптом вне репозитория: они разошлись с движком (у «скор 38+» в подписи
    стояло +5.1% при t=2.06, движок на тех же данных давал +5.7% при t=2.64) и проверить их
    было нечем. Колонка «сверх контроля» строится тем же правилом, что и сигнал: контроль —
    все бумаги, **побывавшие** в том же ценовом контексте в том же месяце (признак сделки
    меряется на дату сделки, то есть в произвольный день месяца). Оборот и издержки считаются
    из состава портфеля, а не назначаются: у трёхмесячного набора оборот втрое выше.

## Развёртывание

1. `backfill.yml` (workflow_dispatch) — картриджный: сам передиспатчивает себя до готовности
   (лимит 12 итераций), затем сам запускает `daily.yml`.
2. `daily.yml` — крон 03:40 UTC вт–сб: живой контур → цены → compute → гейт → Pages + ветка data.
   Гейт публикации: payload с <1000 покупок не публикуется.
3. Секреты (опционально): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — пошагово в
   [НАСТРОЙКА.md](docs/НАСТРОЙКА.md). Проверка: Actions → «Проверка Telegram» → Run workflow.
4. **Внешний cron обязателен**: штатное расписание GitHub опоздало на 7ч46м на первом же
   прогоне и гасится после 60 дней без активности. Инструкция — там же.

## Ограничения (осознанные)

- Нет капитализации и сектора эмитента: вместо капитализации используется прокси по дневному
  $-обороту (micro/small/mid/large). Настоящая капа и SIC — в v3 через companyfacts/submissions.
- Нет дат отчётности, поэтому нет признака «покупка вне blackout-окна» (v3: даты подач 10-Q/K).
- Form 144 (proposed sale) не собирается; деривативная таблица (exercise-and-hold) не анализируется.
- Медвежий канал (флаги на продажах по Larcker 2021, cessation of selling) — v3.
- Цены — Yahoo: делистнутые он не отдаёт вовсе (проверено: `LGCY` → HTTP 400). Дыра
  выжившести измерена и составляет 1512 тикеров; закрывается бэкфилом Tiingo порциями
  по 500 символов в месяц, поэтому до полного покрытия абсолютные доходности завышены.
  Относительные сравнения (сигнал против такой же вселенной) смещены заметно меньше:
  обе стороны берутся из одного и того же кэша.
- Аннулирующие 4/A определяются эвристикой (поправка без строк P/S): часть филеров
  перезаявляет только исправленные строки, поэтому такие сделки помечаются флагом и
  исключаются из сигнала, но не удаляются из данных.
