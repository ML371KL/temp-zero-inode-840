# Лента формы 4 на весь день (840) — выкладка

Что это и зачем — `docs/СБОРКА-НА-VPS.md` (раздел «Лента на весь день»). Здесь — шаги. На сервере: пользователь `dash`, код `/srv/dash/repo-840` (тот же клон),
состояние `/var/lib/insider840-feed` (журнал дня `ГГГГ-ММ-ДД.jsonl`, около 1–3 МБ в день, хранится 14 дней), юнит и таймер
`/etc/systemd/system/insider840-feed.{service,timer}` (таймер: пн–пт 06:00 по Нью-Йорку, сборщик работает до 22:00 ET).

Секретов нет: лента SEC читается с User-Agent проекта, не чаще 2,5 запроса в секунду (с запасом до лимита SEC — 10 в секунду с адреса).
Журнал остаётся на диске VPS: его читает сборка утреннего списка (`insider840-morning`) в 22:03 ET.

## Шаги

1. Слить PR; код на VPS обновляет только установка.
2. `sudo bash ops/insider840-feed/install.sh` — код, каталог состояния, юнит и таймер, пробный такт без записи, включение таймера.
3. Тревоги: в `dash-alert` (репо 839, `ops/dash-alert`) строка `insider840-feed*)  subject="840 · лента форм";  key="feed-840";;`.
4. Контроль: `journalctl -u insider840-feed -e` («старт», «новых разобранных подач», в конце «конец: замечено …»); файл `/var/lib/insider840-feed/ГГГГ-ММ-ДД.jsonl`;
   в 22:03 ET в журнале `insider840-morning` строка «лента: видела N подач, разобрала M; индекс K; нет в индексе X».

## Ручной запуск и откат

- Один такт без записи: `sudo -u dash bash -c 'cd /srv/dash/repo-840 && node scripts/vps/feed-collector.mjs --dir /tmp/feed-probe --once --dry-run'`.
- Остановить: `sudo systemctl disable --now insider840-feed.timer insider840-feed.service` — сборка списка продолжит работать по индексу, сверки с лентой не будет.
- Лента глубже 300 записей за такт не читается: в пик (16:00–17:30 ET) за 45 секунд новых подач меньше, но если сборщик простоял, пропущенное подберёт индекс; «разрыв» виден в журнале.
