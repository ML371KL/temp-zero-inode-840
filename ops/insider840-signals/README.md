# Сигнал в торговые часы (840, контур B бота) — выкладка

Что это и зачем — `docs/СБОРКА-НА-VPS.md`, раздел «Сигнал в торговые часы». Здесь — шаги. На сервере: пользователь `dash`, код
`/srv/dash/repo-840` (тот же клон), состояние `/var/lib/insider840-signals` (режим 0755: файлы сигналов дня читает бот, пользователь
`ib840`; каталог ленты `/var/lib/insider840-feed` остаётся закрытым).

| Юнит | Когда | Что делает |
|---|---|---|
| `insider840-signals-ref` | пн–пт 23:52 и 07:00 ET | справочник D−1: своя копия ветки data, бары вселенной через воркер `/bars`, `compute --intraday-ref` → `ref/<день сигнала>.json`; около 10 минут. Формы — по последний рабочий день SEC (из ветки data или из копии ночной сборки списка); годный справочник не пересобирается, негодный и неполный — пересобирается в 07:00 (не дольше 45 минут) |
| `insider840-signals` | пн–пт 09:25–16:05 ET | читает хвост журнала ленты, считает событие эмитента по справочнику, пишет `ГГГГ-ММ-ДД.jsonl` |
| `insider840-feed` (свой каталог `ops/insider840-feed`) | пн–пт 06:00–22:00 ET | лента; в торговые часы опрос раз в 15 секунд, `CPUWeight=400` |

Секретов не заводит: шаг справочника берёт адрес и токен воркера из env сборки утреннего списка
(`/usr/local/etc/insider840-morning/env`, `PAPER_URL` и `PAPER_TOKEN`); в воркер и в ветку data он ничего не пишет. Процессу сигналов
сеть не нужна.

## Шаги

1. Слить PR; код на VPS обновляет только установка. Окно — после 22:45 ET (ночная сборка списка закончена) или в выходные.
2. `sudo bash ops/insider840-feed/install.sh` — юнит ленты с шагом 15 секунд в торговые часы и `CPUWeight`. Работающую ленту установщик
   не перезапускает: новый шаг начнёт действовать со старта в 06:00 ET.
3. `sudo bash ops/insider840-signals/install.sh` — каталог состояния, четыре юнита, проверка расчёта без записи, включение таймеров.
4. Первый справочник: `sudo systemctl start insider840-signals-ref` (или дождаться 23:52 ET). В журнале — «вселенная: N бумаг»,
   «источник ответил по N из M», «справочник на ГГГГ-ММ-ДД по барам ГГГГ-ММ-ДД: бумаг N», «готово».
5. Тревоги: `dash-alert` новые юниты пришлёт именем юнита («VPS · insider840-signals»). Человеческие имена — две строки в `dash-alert`
   (репо 839, `ops/dash-alert`), по образцу `insider840-feed*`.

## Контроль

- `journalctl -u insider840-signals -e`: «старт: день …, справочник по барам … (бумаг N)», строки «СИГНАЛ …», в 16:05 — «конец:
  сигналов N, пропусков M».
- Файл дня `/var/lib/insider840-signals/ГГГГ-ММ-ДД.jsonl`: `run`, `sig`, `skip`, раз в час `stat` (задержка «принято SEC → запись
  формы в журнале ленты»: `med`, `p90`, доля не позже 90 секунд `ok90`).
- `ls -l /var/lib/insider840-signals/ref/` — справочники последних десяти дней.

## Тревоги и что они значат

| Что пришло | Причина | Что будет |
|---|---|---|
| `insider840-signals-ref` упал | ветка data или воркер не ответили за полтора часа, compute упал; либо справочник собран, но не годен: «СОБРАН, НО НЕ ГОДЕН» в журнале — формы старше последнего рабочего дня SEC или справочники иностранных эмитентов не готовы | в 07:00 ET — повтор; не собрался и он — в 09:25 процесс сигналов запишет `off`, контур бота в этот день молчит |
| `insider840-signals` вышел с кодом 3 | сигналов сегодня нет: справочника на сегодня нет, он не на тот день или справочники иностранных эмитентов не готовы (`fpiWarn`) | запись `off` в файле дня, перезапуска нет; бот выключает контур до конца дня |
| `insider840-signals` вышел с кодом 1 | медиана задержки ленты за час выше двух минут (не чаще раза в час) либо сбой процесса | перезапуск через 15 секунд, записанные сигналы не повторяются |

## Ручной запуск и откат

- Расчёт по уже лежащему журналу без записи: `sudo -u dash bash -c 'cd /srv/dash/repo-840 && node scripts/vps/signal-watch.mjs --once --dry-run'`.
- Справочник заново: `sudo systemctl start insider840-signals-ref` (готовый на этот день не пересобирается; принудительно — запуск
  скрипта с `--force` от пользователя `dash` с env сборки списка).
- Остановить сигналы: `sudo systemctl disable --now insider840-signals.timer insider840-signals.service insider840-signals-ref.timer`.
  Бот без свежего файла сигналов в контур не входит. Сборку утреннего списка и ленту это не задевает.
- Вернуть ленте прежний шаг: убрать `--rth-interval 15` из юнита (или `--rth-interval 0`), `systemctl daemon-reload`; подействует
  со следующего старта ленты.
